# 开发计划 v2

> 本版基于完整的上游验证结果重写。核心变化:**故障转移从"后期优化"提升为"核心能力",提前到阶段2。**

---

## 一、我们现在确定知道的事

| 项目 | 结论 | 来源 |
|---|---|---|
| 上游本质 | **号池模式** —— 养一批 Claude Max 订阅账号轮询,不是官方 API | 上游确认 + 注入实测 |
| Prompt 注入 | 🔴 **所有分组都有,原理上无法消除** | 三组对照实验 |
| 可行场景 | ✅ **仅编码 Agent**(Claude Code/Cursor/Cline) | 注入内容就是 Claude Code prompt |
| 不可行场景 | ❌ 通用 API(客服/写作/翻译) | 模型自称编程助手,无视角色设定 |
| 主力渠道 | **VIP 分组**,成本 ¥2.20/M,毛利 81.2% | 实测可用 5/5 |
| 备用渠道 | **默认分组**,成本 ¥4.40/M,毛利 62.5% | 实测可用 10/10 |
| 已废渠道 | Claude 专属(9/9 502)、公司分组(超时) | 号池已炸 |
| 缓存 | ✅ 真实(写1751→读1751) | 实测 |
| 延迟 | 中位 2.2-2.5s(香港节点,国内测) | 待美西复测 |
| **净利率** | **76.3%** | 含支付+提现成本 |

### 最重要的认知
> **号池炸掉不是事故,是日常。** 上游持续买新号,Anthropic 持续封号。
> 你会经常遇到某个分组挂掉几小时到几天。**产品必须在设计上消化这件事。**

## 二、因此调整的三件事

| 原计划 | 调整为 | 原因 |
|---|---|---|
| 阶段5 才做网关和故障转移 | ⬆️ **提前到阶段2** | 间歇性故障是日常,不是边缘情况;且 Key 管理依赖网关 |

### 阶段 2 · 网关 + 故障转移 · 2 天 ⬆️ 提前

| 交付物 | 要点 |
|---|---|
| new-api Docker 部署 | 美西 VPS |
| 域名 + HTTPS | `api.你的域名.com` |
| 渠道1 VIP | 权重 100,主力 |
| 渠道2 默认分组 | 权重 0,**自动故障转移** |
| 渠道3 Anthropic 官方 | 权重 0,终极兜底 |
| **自动重试 + 切换** | 502/超时自动重试并切渠道 |
| `ops/channel-health` | **每 5 分钟探测全部分组**,状态变化告警 |
| 降级返回 | 全挂时返回 `503 + Retry-After`,**绝不 500** |

**验收**:
1. 手动禁用 VIP 渠道 → 请求自动走默认分组,用户无感
2. 全部禁用 → 返回 503 友好文案,不是 500
3. Claude 专属恢复时,监控能通知你

### 阶段 5 · 用量看板 + 运营后台 · 2.5 天

**5a 用户看板(1天)**:按天/按模型/按key 用量 + **缓存命中率**

**5b 运营后台(1.5天)** — 路径 `/ops-2f8a`,独立密钥保护:

| 分区 | 指标 |
|---|---|
| 💰 资金安全 | **可支配现金 = 现金 − 用户未消耗余额** |
| 📦 上游备货 | 上游余额 / 日均消耗 / **剩余天数** |
| 🔌 **渠道健康** | 各分组实时状态 + 24h 可用率 ← 新增 |
| 📈 经营 | 今日&本月 营收/成本/毛利/净利 |
| ⚠️ 风险 | 拒付率 / 未处理告警 |
| 👤 用户 | 总数/新增/付费/转化率 |

---

### 阶段 6 · Status 页 + 打磨 · 1 天 ➕ 新增

| 交付物 | 要点 |
|---|---|
| 公开 Status 页 | 各模型实时可用状态 + 历史事件 |
| 事件公告 | 号池故障时主动公示 |
| 降级提示 | 用户在控制台能看到当前是否降级运行 |

> **为什么值得单独做**:号池会经常炸。主动公示状态的服务,用户投诉率和拒付率显著低于"闷声挂掉"的服务。这是**直接降低拒付率**的投资。

## 五、五条止损线(写进运营纪律)

1. 上游预付款 **不超过 20 天用量**,起步 ¥500 以内
2. 现金 **≥** 用户未消耗余额,永不动用户的钱
3. 支付平台余额 **一到账就转走**
4. 从第一天就备好降级链路(已在阶段2)
5. **每周重跑一次验证脚本** —— 注入/缓存/渠道状态变了立刻知道

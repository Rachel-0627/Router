## 二、🔴 Prompt 注入 —— 三组对照实验

### 实验 B(决定性证据)
发送的 system(重复三遍强化):
```
You are Blackbeard the pirate. You know NOTHING about computers or software.
You have NO tools of any kind. Always speak in pirate dialect.
```
模型返回:
```
I'm NOT, an AI coding assistant. I write code, edit files,
run terminal commands, search codebases...
```
→ **用户的 system prompt 被注入内容完全覆盖。**

### 实验 C
未定义任何工具,模型自称拥有:文件读取、文件编辑、文件创建、搜索、**终端命令执行**、网页访问
→ 这是 Claude Code 的标准工具集。

### 实验 D(反向验证)
明确定义 `get_weather` 一个工具后要求读文件 → 模型正确拒绝,**没有**幻觉出 Read/Bash。

### 判定
**上游是逆向 Claude Code 订阅额度,不是官方 API。**
- 解释了为何价格只有官方 6-12%(订阅制摊薄)
- `usage_source: "anthropic"` 属实,但走的是订阅通道非 API 通道
- 注入影响**模型人格层**,不影响**工具调用层**

## 三、影响分级

| 场景 | 可用性 | 说明 |
|---|---|---|
| **Claude Code / Cursor / Cline** | ✅ **可用** | 注入的就是 Claude Code prompt,用户本来也在跑编码 Agent;工具调用正确 |
| 通用 API 转售(客服/写作/翻译) | ❌ **不可用** | 模型自称编程助手,忽略角色设定,必然导致退款差评 |

→ **原定的「编码 Agent 专用」定位,是唯一可行的定位。**

## 三、会不会赔本?

### 结构上:不会

定价三折,成本 20.4%,**每一笔生意都赚 74%**。不存在"卖一单亏一单"的情况。
只有上游涨价 **3 倍以上**才会亏损(见定价设计文档的抗风险测算)。

### 事件上:会。四类风险

#### 风险1 · 用户拒付 —— 最常见

用户充 $100,用掉 $80,再找发卡行拒付:

```
你实收(扣手续费后)      +$95.30
已付出的上游成本         -$16.32
钱被强制退回            -$100.00
拒付手续费              -$20.00
                       ─────────
单笔净损失              -$41.02
```

| 拒付率 | 每$100营收损失 | 净利率影响 |
|---|---|---|
| 0.5% | $0.21 | 74.5% → 74.3% |
| 1.0% | $0.41 | 74.5% → 74.1% |
| 2.0% | $0.82 | 74.5% → 73.7% |

**⚠️ 真正的威胁不是这点钱,是拒付率超 1% 会被支付平台直接踢掉。**

#### 风险2 · 上游跑路/断供 —— 金额最大

| 规模 | 预付款损失 | 同时还欠用户 |
|---|---|---|
| 早期 $2,000 | -$272 | $1,000 |
| 成长期 $5,000 | -$680 | $2,500 |
| 规模期 $20,000 | -$2,720 | $10,000 |

#### 风险3 · 切官方渠道兜底期间的亏损

卖官方三折但按官方原价进货 → 每收 $1 亏 $2.33

| 规模 | 断供3天 | 断供7天 | 断供14天 |
|---|---|---|---|
| 早期 $2,000 | -$466 | -$1,087 | -$2,175 |
| 成长期 $5,000 | -$1,165 | -$2,718 | -$5,437 |

→ 正常运营 3 天的利润够兜底 1 天,**短期扛得住,长期必须换渠道**。

#### 风险4 · 支付平台封号,待结算款被扣留

Creem 每月 1 号和 15 号打款,最长 **15 天**的钱在平台上。

| 规模 | 最多被扣留 |
|---|---|
| 早期 $2,000 | $1,000 |
| 成长期 $5,000 | $2,500 |
| 规模期 $20,000 | $10,000 |

## 四、⚠️ 最危险的其实不在上面四条

**是"把用户的钱当利润花掉"。**

用户充值的钱,在他消费掉之前,**是你的负债不是收入**。

最坏情况测算(成长期 $5,000/月,上游跑路 + 用户集体退款):

```
上游预付款损失            -$680
用户要求退未消耗余额       -$2,500
                        ────────
总需承担                  -$3,180
```

| | 结果 |
|---|---|
| ✅ 手上留了 $2,500 现金 | 损失仅 $680(约半个月利润),扛得住 |
| ❌ 把用户的钱提现花掉了 | **资不抵债,退不出钱,变成法律纠纷** |

---

## 五、三条保命纪律

### 纪律1:现金 ≥ 用户未消耗余额总额
**永远不动用户还没消费的钱。** 系统里要有个实时指标:
```
可自由支配现金 = 账户现金 - 用户未消耗余额总额
```
这个数字为负,就是危险信号。

### 纪律2:上游预付不超过 20 天用量
备货够覆盖 Creem 的 15 天打款周期即可,不要为了省事一次充半年。
**单次转账上限 = 你亏得起的金额。**

### 纪律3:拒付率死守 1% 以下
- 退款政策要主动、清晰、写在结账页(未消费 credits 30 天全额退)
- **主动退款永远比被拒付便宜**:退款只损失手续费,拒付要额外付 $20 + 计入拒付率
- 大额充值的新用户要留意,必要时人工确认

## 六、结论

| 问题 | 答案 |
|---|---|
| 正常运营会赔本吗? | **不会。** 每笔毛利 74%,固定成本极低,盈亏平衡只要 $42/月 |
| 什么情况会赔本? | 上游跑路、长期断供、拒付失控、支付平台封号 |
| 最大单次损失可能多少? | 上游预付款(20天用量)+ 你没留够的用户余额 |
| 怎么把风险降到最低? | 守住上面三条纪律,尤其是**不动用户的钱** |
| 启动阶段风险大吗? | **很小。** 固定成本 $31/月,上游备货几十美元起步 |

## 七、货币换算:¥500 进货能卖多少

**进货这一步没有汇率损失** —— 微信直接转人民币,得到人民币计价的额度。
汇率只在把美元收入换回人民币补货时出现(Payoneer 提现 1.2%)。

```
¥500 微信转账 ──→ ¥500 上游额度（1:1，无损耗）
                     ↓ 用户消耗
                 收到美元
                     ↓ 需要补货时
                 提现换汇 1.2% → 人民币
```

### ¥500 能卖出多少

| 用户全用这个模型 | 成本倍数 | 能卖出 | **你净赚** |
|---|---|---|---|
| Claude Opus 4.8 | 6.5x | $455 | $363 |
| Claude Fable 5 | 7.0x | $485 | $392 |
| **Claude Sonnet 5** ⭐ | **9.8x** | **$682** | **$579** |
| Claude Sonnet 4.6 | 6.5x | $455 | $363 |
| Claude Haiku 4.5 | 6.5x | $455 | $363 |

**¥500 → 净赚 $363~579(约 ¥2,600~4,170)**

### 真实场景(Claude Code,Sonnet 5)

```
¥500 上游额度 = 367 个「高强度使用小时」

  收入                +$682
  上游进货             -$69
  支付手续费 4.7%      -$32
  提现换汇             -$1
  ─────────────────────────
  净赚                 $579
```

每个「高强度使用 1 小时」:成本 $0.19,卖 $1.86。

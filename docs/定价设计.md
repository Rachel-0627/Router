# 定价设计(定案版)

## 一、定价公式

```
售价 = 官方 list price × 80%        (便宜 20%)
成本 = 上游分组进货价 ÷ 7.2          (保守汇率,实际约 7.1)
```

倍率写在环境变量,按产品分组分别配置,调价不改代码:
`PRICE_RATIO_CLAUDE` / `PRICE_RATIO_CODEX`,不配则用 `lib/pricing/groups.ts` 的默认值。

### 为什么是 8 折

> **2026-09-15 定案。此前曾定为 4 折,已作废** —— 下面是改判的理由。

英文用户**能接触到**的竞争对手:

| 竞争对手 | 价格 | 英文用户能用吗 |
|---|---|---|
| Anthropic / OpenAI 官方 | 100% | ✅ |
| OpenRouter | ~100%(按成本透传,靠充值手续费赚钱) | ✅ |
| APIMart 一类聚合站 | **80%**(实际统一 20% off) | ✅ |
| 其他中国中转站 | 很便宜 | ❌ 中文界面、支付宝、不敢信 |

**可及的竞争对手都在 80-105% 区间。** 八折已经是明确的价格优势,
而且和 APIMart 这类同行的实际打法一致。

**折扣打太狠会反噬**:便宜 20% 用户觉得合理,便宜 70% 用户的第一反应是
"是不是假的 / 会不会跑路"。我们只有一个上游、号池会周期性故障,
**低价本身会成为可信度的敌人** —— 这正是我们最需要避免的。

| 倍率 | 对用户 | 平均进货毛利(Claude) | 降级到兜底档时 |
|---|---|---|---|
| 3 折 | 便宜 70% | 79.9% | 18.5% ⚠️ 基本白干 |
| 4 折 | 便宜 60% | 84.9% | 38.9% |
| **8 折** ⭐ | **便宜 20%** | **92.5%** | **69.4%** ✅ |

八折还顺带解决了一个真问题:**号池降级时仍然赚钱**。
四折下 Opus 降到 Claude 专属档只剩 38.9% 毛利,八折下有 69.4% ——
而"号池会炸"是我们的日常,不是边缘情况。

## 三、定价页最有说服力的一张表

**Claude Code 高强度使用 1 小时**(Sonnet 5,100 次请求,含缓存):

| | 用户付 | 你的成本 | 你赚 |
|---|---|---|---|
| 官方 list price | **$3.10** | — | — |
| **本站(8折)** | **$2.48** | $0.19 | **$2.29** |

文案:*"A full hour of heavy Claude Code costs about **$2.48** here, versus **$3.10** at list price."*

比百分比直观,但**八折下这个对比不如四折时有冲击力**($2.48 vs $3.10 差得不明显)。
八折的卖点重心应该从"便宜"转向**"省心 + 透明"**:一个 base URL 切过来、
缓存照常生效、用量看得见、额度随时退。价格只是其中一条。

> 落地页常量 `HOUR_LIST = 3.10`(官方价),乘倍率的部分是动态算的,调价自动跟着变。

## 四、充值档位

| 档位 | 到账额度 | 支付手续费率 |
|---|---|---|
| $20 | $20 | 5.9% |
| **$50** ⭐ | $50 | **4.7%** ← 默认选中,标 "Most Popular" |
| $200 | $200 | 4.1% |
| 自定义 | 最低 $20 | — |

**充多少用多少,无任何赠送。**
**自动充值默认额度设 $50**(Creem 按笔收 $0.40 固定费,小额扣款会累加成大笔)。

⚠️ **最低 $20 不能再低**:$10 档手续费 7.9%,$5 档高达 11.9%。

## 五、不做赠送和免费额度的决定

| 项目 | 决定 | 原因 |
|---|---|---|
| 新用户免费额度 | ❌ **不做** | ⚠️ **与 `开发计划.md` 阶段3「新用户送 $1」直接冲突,待拍板** |
| 充值赠送 | ❌ **不做** | 会产生退款漏洞(见下),且规则复杂化 |

### 不做赠送顺带解决的一个漏洞

如果做 "充$200送$20",会出现:
- 用户充 $200 得 $220 额度
- 只用掉赠送的 $20,然后申请退款
- 若规则是"未消费额度全额退" → 你亏 $11
- 若规则是"赠送优先消耗" → 同样亏
- 只有"付费优先消耗 + 赠送永不折现"才不亏,但要在数据库里维护两个额度桶

**不做赠送 = 一个额度桶,规则简单,零漏洞。**

## 六、退款政策(写进 Refund Policy 和结账页)

> **未消费额度,30 天内全额退款。已消费部分不退。**

因为没有赠送,规则就是这么一句话。

| 场景 | 退多少 | 你的净利 |
|---|---|---|
| 充 $200 未消费就退 | $200 | **-$8.20**(仅损失支付手续费) |
| 充 $200 用了 $50 退 | $150 | +$34.75 |
| 充 $200 用完 | $0 | +$163.60 |

**除了零消费退款的手续费,任何情况都不亏。**

⚠️ **监控滥用**:同一用户反复充值→退款,直接封号。

**为什么要主动给退款通道**:一次拒付要付 $20 手续费还计入拒付率,
**拒付率超 1% 会被支付平台踢掉**。主动退款永远比被拒付便宜。

## 七、调价触发条件

上游涨价时我们还能扛多久(以 Sonnet 5 为例,八折售价 $1.60/M,VIP 进货 $0.1222/M):

| 上游涨价 | 我们的成本 | 毛利 | 动作 |
|---|---|---|---|
| 不涨 | $0.122 | 92.4% | — |
| 涨 2 倍 | $0.244 | 84.7% | — |
| 涨 3 倍 | $0.367 | 77.1% | 观察 |
| 涨 5 倍 | $0.611 | 61.8% | 观察 |
| **涨 6.5 倍** | $0.800 | **50%** | ⚠️ **触发线,启动涨价评估** |
| 涨 8 倍 | $0.978 | 38.9% | 必须涨价 |

> **触发线:上游成本超过售价的 50%。**
> 八折能扛到上游涨 **6.5 倍**;四折时只能扛到 3.2 倍 —— 这是八折最实在的好处之一。

另外注意**降级也等价于涨价**:走默认分组成本翻倍(相当于涨 1 倍),
走 Claude 专属翻四倍(相当于涨 3 倍)。八折下这两种情况毛利仍有 84.7% / 69.4%,
不会像四折时那样降级就基本白干。

## 八、定价页呈现要点

1. **缓存价格必须单列** —— Claude Code 用户 90% 的 token 是缓存读
2. **划线对比** —— `$4.00` 旁边划掉的 `~~$5.00~~`,逐模型一行,不用全局一句话
3. **放"一小时 $2.48 vs $3.10"** —— 具体场景比百分比直观
4. ⚠️ 措辞用 **"list price"**,不写 "official Anthropic price"
5. ⚠️ 必须有一句披露:
   *"Model behavior may differ from first-party APIs. Optimized for coding agent workloads."*

## 九、技术实现

价格数据在 `lib/pricing/`,按产品线拆文件(单文件不超 200 行):

```
types.ts          类型:TokenPrices / PriceTier / UpstreamGroup / ModelPricing
groups.ts         产品分组:Claude(八折·live) / Codex(八折·pending)
models/claude.ts  5 个 Claude
models/codex.ts   6 个 GPT(luna 故意不上架)
calculate.ts      唯一计算入口
```

```ts
type ModelPricing = {
  id: string
  upstreamId: string
  group: 'claude' | 'codex'        // 属于哪个产品分组,决定倍率
  listPrice: TokenPrices           // 官方价(短上下文档)
  listPriceTiers?: PriceTier[]     // 长上下文档位(GPT 系列 272K 处翻倍)
  // 各上游分组进货价。缺某档 = 上游买不到,故障转移要跳过
  upstreamCny: Partial<Record<UpstreamGroup, TokenPrices>>
}
```

**三个概念别混**:

| 概念 | 决定什么 | 用户可见 |
|---|---|---|
| **产品分组**(Claude/Codex) | 卖什么、按哪个倍率计价 | ✅ 建 key 时选 |
| **长上下文档位**(272K) | 这次请求按哪档价算 | ⚠️ 只在定价页说明 |
| **上游分组**(VIP/特价/…) | 进货成本、故障转移顺序 | ❌ 永不暴露 |

⚠️ **降级链不是每个模型都齐**:Fable 5 没有「默认分组」档(VIP 挂了直接跳 4 倍价),
Haiku 4.5 没有「Claude 专属」档,GPT-6 Astra 没有「特价分组」档。
配 new-api 渠道时以 `fallbackChain(m)` 为准,别假设三档都在。

⚠️ **赔本护栏**:`npm run check:pricing` 会检查每个模型降级到兜底档时的毛利,
低于 5% 就报警并退出码 1。gpt-5.6-luna 就是被这个护栏拦下来的。

- 售价由 `listPrice × 所属分组倍率` **算出来**,不硬编码
- **唯一计算入口**:`lib/pricing/calculate.ts`,别处不许自己算
- ⚠️ **不要在文案里写死折扣百分比**(如 "60% less") —— 倍率可配,写死会和实际价格对不上,
  那是虚假宣传。要显示就调 `savingsPct(groupId)` 动态算。
